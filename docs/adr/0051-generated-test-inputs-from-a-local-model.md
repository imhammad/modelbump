# ADR 0051: Have a local model write the missing test inputs, and mark every one as generated

- **Status:** Accepted
- **Date:** 2026-10-28

## Context

[ADR 0050](0050-test-inputs-from-the-apps-own-callers.md) takes test inputs from the values an app's own code passes in. On five open-source apps it found 1 case for 82 calls, so most calls need inputs from somewhere else. The master plan's next source is inputs a model writes within the limits of the prompt template. Three constraints apply:

- **No money, no leaks.** Inputs are written from the app's prompts, which are the app's code. A local model keeps them on the machine, at no cost ([ADR 0036](0036-runner-speaks-openai-compatible-http.md)).
- **Reproducible.** The same command must give the same inputs, or the suite changes under the comparison.
- **Honest.** A generated input is not one the developers chose, and a reader of a report must be able to tell the two apart.

## Decision

- **`modelbump cases PATH --generate N`** has a writer model add cases until each call with slots has `N` complete cases. Cases from the app's code count first. Calls with a fixed prompt need none. Calls with a message that cannot be read (`history`) are not asked, because their cases could never be complete.
- **The writer is `ollama/qwen2.5:7b` by default** (`--generator` picks another, as `endpoint/model`). A cloud tier works but prints the same warning as `modelbump ask` first, since the app's prompts would leave the machine.
- **One request per call** (`src/modelbump/synth/generate.py`). The request shows the call's API, model, place and every message template with its `{slots}`, and asks for exactly the number of value sets still missing, as a JSON array of objects with exactly the slot names as keys. It asks for realistic and varied inputs: typical ones, short and long ones, and unusual or tricky ones. Temperature 0.8, at most 250 tokens per case.
- **Strict reading.** The JSON array may sit inside prose or a code fence. A set that misses a slot, or has a list or object as a value, is dropped. Numbers and booleans become text. Extra keys are ignored. Duplicate cases are kept once.
- **Rounds.** A call that is still short gets another request with the next sample number, up to 3 rounds (`MAX_ROUNDS`). A call that is still short after that, or whose request fails, is listed on stderr with the reason, and the other calls go on.
- **Reproducible.** The round number is both the seed and the cache sample, and the Ollama digest pins the weights in the cache key ([ADR 0037](0037-response-cache-in-sqlite.md), [ADR 0039](0039-pin-local-models-to-their-digest.md)). Running the same command again reads every answer from the cache and prints the same cases. `--budget-requests` caps the requests ([ADR 0038](0038-budget-in-tokens-and-requests.md)).
- **Marked.** A generated case has `generated_by` (the writer model) and the source `generated by ollama/qwen2.5:7b, sample 0`, in the text and JSON reports. The summary counts generated cases on their own.
- **Values are put in as text.** A value is placed in the template as it is, with any braces kept literal, so a generated `{code}` can never become a slot.

## Alternatives considered

- **Templates or grammars instead of a model** (random strings, Faker): free and fast, but they know nothing about what a ticket, an email or a research question looks like, so the cases would not test the app's real behaviour.
- **The model under test writing its own inputs:** convenient, but it could favour inputs it handles well. The writer is a fixed, separate choice instead, recorded on every case. When the comparison is Qwen 2.5 against Qwen 3, the default writer is one of the two models, which is a threat to validity to report. `--generator` lets an experiment pick an unrelated writer.
- **JSON mode (`response_format`):** Ollama's JSON mode returns one object, not an array, and not every free endpoint supports it. Asking for an array and reading it strictly works on all of them.
- **Asking for one case per request:** simpler to read, but the model cannot see what it already wrote, so the cases come out much more alike, and it costs more requests.

## Consequences

- Every call whose messages can be read can now get `N` complete test cases, on a laptop, at no cost.
- The generated inputs are only as good as the writer. Whether they are realistic, and how much they differ from the app's real traffic, is something to measure, for example by hand-labelling a sample with the judge calibration of Phase 5.
- What a correct answer is for each case (the oracle) is not decided here. That is the next step.
